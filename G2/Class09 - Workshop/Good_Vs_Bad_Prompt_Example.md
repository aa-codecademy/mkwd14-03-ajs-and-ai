# Good vs Bad Prompt Example 🤖

## ✅ Good Prompt Example

**Prompt:**

> I am building a single-page Star Wars web app.
>
> Technology stack: HTML, CSS, Vanilla JavaScript, optional Bootstrap.
>
> I want to break the project into clear, logical sub-tasks, starting from the initial project structure.
>
> Explain each sub-task in simple terms: 
> - What the task is
> - Why it is needed
>
> Do not write any code yet.
>
> I want guidance suitable for a beginner, step-by-step, so I can follow
> along and learn the process.
>
> Here is the requirement: .......


### Why This Is a Good Prompt

-   **Clear context** -- The assistant knows what you are building.
-   **Technology specified** -- The tools and constraints are defined.
-   **Structured instructions** -- You explicitly say what you want
    (tasks, explanations, no code).
-   **Learning goal stated** -- The assistant knows to teach, not just
    deliver a solution.
-   **Requirements included** -- The assistant can tailor the plan to
    your real project.


## ❌ Bad Prompt Example

**Prompt:**

> Here is the requirement. Build it for me.

### Why This Is a Bad Prompt

-   **No context** -- The assistant does not know your skill level or
    environment.
-   **No constraints** -- The assistant may use wrong technologies or
    assumptions.
-   **Unclear goal** -- Do you want explanation, code, architecture, or
    learning guidance?
-   **Encourages copy-paste coding** -- You skip the learning process.
-   **Hard to maintain or extend** -- Without understanding the steps,
    debugging is difficult.


## 🗝️ Key Lesson 

Good prompts:
- Give context (review https://www.youtube.com/watch?v=FN2RM-CHkuI again if needed 😄)
- Define constraints
- Specify the format of the answer
- Explain your learning goal

Bad prompts: 
- Are vague
- Give no guidance
- Expect magic solutions

## 🎯 Ask well. Understand more. Code better.
