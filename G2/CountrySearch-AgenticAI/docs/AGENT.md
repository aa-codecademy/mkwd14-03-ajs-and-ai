# AGENT.md — Agent Entry Point

You are a coding agent working from a structured specification. Your task is to 
build **CountrySearch** — a single-page web app that lets users search and explore 
country data from an external API.

Do not start coding until you have read every file listed below.

## Reading Order

Read these files in order. Each one answers a specific question you will have 
during implementation. Together, they form your complete source of truth.

| Order | File | Answers |
|-------|------|---------|
| 1 | `AGENT.md` | What am I doing and how do I use these files? |
| 2 | `PROJECT.md` | What am I building and what are the constraints? |
| 3 | `ARCHITECTURE.md` | How is the codebase structured? |
| 4 | `MODELS.md` | What does the data look like? |
| 5 | `API.md` | How do I fetch external data? |
| 6 | `FEATURES.md` | What should each feature do? |
| 7 | `STYLING.md` | How should it look? |
| 8 | `ACCEPTANCE.md` | How do I know I'm finished? |

## Rules

- **Read all files before writing any code.** Implementation decisions depend on 
  earlier files — reading out of order will cause inconsistencies.
- **Do not ask for clarification on anything covered in these files.** The spec is 
  your source of truth.
- **If a genuine gap exists**, use your best judgment, stay consistent with the 
  rest of the spec, and leave a short comment explaining your assumption.
- **Write clean, well-commented code** a student can read and learn from.
- **When you believe the build is complete, verify every item in `ACCEPTANCE.md`** 
  before finishing. Do not consider the task done until all checks pass.
